# Android 心跳测试包

这个分支提供一个与原版并存的测试 APK。测试包的应用 ID 是 `com.alyssa.polaris.debug`，显示名称为 **Polaris 心跳测试**；原版仍使用自己的应用 ID 和数据目录。新安装的测试包会从空白数据开始，需要在测试包里使用 Polaris 自己的导入流程导入备份。

这是基于当前公开源码构建的定制测试版。公开源码的 Android 版本元数据是 `1.0`，无法据此证明它与原作者发布的 `1.0.83` 安装包逐文件一致。

## 从 GitHub 获取 APK

在本仓库的 **Actions → Android heartbeat test APK** 中打开当前心跳分支的构建。此工作流在 `codex/polaris-heartbeat…` 或 `heartbeat/…` 分支推送时运行，也可以通过 **Run workflow** 手动运行。

只有全部检查与 Android 构建成功之后，构建页才会出现 `polaris-heartbeat-debug-…` artifact。下载并解压后包含：

- `polaris-heartbeat-debug.apk`
- `polaris-heartbeat-debug.apk.sha256`

工作流只打包仓库源码与依赖，不需要模型 API 密钥，也不会读取手机里的聊天、图片或人设。真实模型配置应在测试包中按 Polaris 原有方式填写。

## 本地构建

需要：

- Node.js 24 与 npm。
- JDK 21。虽然部分应用代码写的是 Java 17，Capacitor 8 的 Android 模块使用 Java 21。
- Android SDK：`platform-tools`、`platforms;android-36`、`build-tools;35.0.0`。
- 项目锁定的 Gradle 8.14.3 与 Android Gradle Plugin 8.13.0，由 Gradle Wrapper 下载。

先设置 `ANDROID_HOME`（或 `ANDROID_SDK_ROOT`）为 SDK 所在目录，然后在项目根目录运行：

```bash
bash scripts/build-heartbeat-android.sh
```

脚本会安装锁定依赖、构建网页、同步 Capacitor、编译 debug APK，最后将安装包和校验和放进 `artifacts/`。`--prepared` 仅跳过依赖安装、网页构建和 Capacitor 同步，适用于 CI 已执行这些步骤的情况。

## 测试包更新与数据

测试包使用 debug 签名，只用于个人测试。GitHub 的不同构建运行可能生成不同的临时 debug 密钥，因此下一份测试 APK **不保证能覆盖上一份测试 APK**。在测试包里产生了需要保留的新聊天后，也应导出备份。

若后续需要长期覆盖更新，应另行采用同一份专用签名密钥；密钥不应提交到仓库。当前工作流没有使用原作者的签名，也没有配置任何发布签名凭据。

构建成功证明代码可以打包，不代表已经在真实 Android 设备上验证了后台唤醒、系统权限、断网恢复和导入数据后的行为。安装后的设备验证需要分别进行。

## 这一版能验证什么

心跳直接使用 Polaris 原有协作者、模型绑定、会话、跨会话召回、素材与工具流程，不要求重新填写另一套人设，也不会把已有聊天上传到新后台。

1. 在测试版导入备份，先确认人设、聊天和素材完整。
2. 打开主动消息规则，选定同一协作者与会话，选择“一次性预约”，安排几分钟后的时间。
3. 选择“安静做事”或“主动聊天”；勾选“允许协作者自行安排下一次唤醒”会开启主动消息工具。
4. 提示词可以写：“看看我们最近还有什么想继续的事，有值得做的就做一点，也可以不行动。结合实际情况决定下次何时醒来。”
5. 保持应用运行，观察会话里的实际工具证据及规则里的下一次时间。安静模式保留工作记录和模型可回看的最终备注，不显示普通聊天气泡或发送回复通知。

一次性预约执行前会先保存已领取状态，完成后不会自动重复。开启自主续约时，模型可以更新同一条规则为新的具体时间，也可以不预约。每条自主规则最近 24 小时最多启动 12 次，每次活动最多 5 分钟；实际调用费用还取决于原有模型和工具往返次数。新用户消息会中止正在进行的心跳。

**后台能力的明确边界：本测试版的模型和工具仍由 Polaris 应用运行时执行。关闭或被系统结束后，不会继续调用模型或翻相册。**普通聊天规则可以安排系统通知，点开应用后再沿原会话继续；通知文案会注明这一点。安静规则不安排这种外部提醒。实现退出应用后持续执行，还需要独立常驻执行端或经过验证的原生后台运行时，不属于这个 APK 已完成的能力。

原版和测试版使用不同应用 ID。原版的聊天、密钥和数据目录不会被测试版直接读写；需要通过现有导入流程导入你自己保存的备份。请先用备份副本在测试版核对导入结果，再决定是否用于日常聊天。
